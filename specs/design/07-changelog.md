# v3 — 정적(靜的) Quiet Console (2026-07-27 ~)

**브랜치** `feat/design-v3` · **작업 루트** `/home/mooner92/keiwi-design`(worktree, dev :3106)
**첫 커밋** `e1249e3` — 토큰 체계 전면 교체 + `/about` 소개 페이지

## 왜 v2를 버렸나

**트리거.** v2(KRDS 이식)를 규격대로 완성할수록 화면이 **더 안 읽혔다.** 증상 목록:
- 본문 17px + 32px H1 + 48~80px 섹션 리듬 때문에 크롬이 뷰포트의 40%를 먹었다. 정작 주인공인 Grafana
  임베드가 밀려나 세로 스크롤이 생겼다.
- 정상 노드가 초록, 성공이 초록, 브랜드도 초록, 활성 탭도 초록, 링크는 파랑. **화면 전체가 색칠 공부**가 되어
  진짜 장애(빨강) 하나가 묻혔다.
- 카드마다 그림자가 있어 12개 노드 카드가 일제히 떠 있었고, hover하면 `-translate-y-0.5`로 들썩였다.
  상주 관제 화면에서 이 움직임은 **거짓 이벤트 신호**였다.
- 반경이 2/4/6/10/12로 제각각이라 화면이 여러 재질로 보였다.

**진단.** KRDS는 **대민 서비스**(불특정 다수·저빈도·저학습)용 규격이다. 관제 콘솔은 정반대
(소수·상주·고학습)다. 규격을 잘 지킬수록 맥락에 안 맞는 결과가 나오는 구조였다.

**결정.** KRDS 원칙 폐기. **서체(Pretendard GOV)만 존치** — 규격 준수가 아니라 품질(한글 판독성 +
tabular 숫자 + 실파일 4종) 때문이다.

## 무엇을 버렸나

| 버린 것 | 왜 |
|---|---|
| 정부 회색 램프(`gray-0`~`100`)·`success-*`·`info-*`·`neutral-*`·`warning-*` **모든 숫자 스텝** | 램프가 노출되면 "적당한 스텝"을 골라 쓰게 되고 역할 토큰 체계가 무너진다. v3의 색은 **역할 이름으로만** 존재한다 |
| `success` 계열 전체 | 정상을 초록으로 칠하면 화면 기본 상태가 초록 카펫이 되고 빨강 하나가 묻힌다. **유채색은 문제에만** |
| `info` 계열(파란 링크) | 링크는 밑줄이 어포던스를 전담. 문서에 링크 20개면 파랑 20개가 흩어진다 |
| 본문 17px · H1 32px · Display 60/44/36 | 위계를 크기가 아니라 **굵기 + 잉크 계조**로 만들기로. 최대 24px, 본문 14px(−18%) |
| 요소별 반경 2/4/6/10/12 | 화면이 한 재질로 보이도록 4/6/8/full로 축약, **8px 상한 고정**(`radius-xl`~`3xl`도 8px) |
| 카드 그림자(sm) · hover 그림자 상승(md) | 카드는 다른 레이어에 있지 않다. 그림자를 팝오버 전용으로 남겨야 그림자가 "임시로 뜬 것" 신호가 된다 |
| `hover:-translate-y-0.5` | 주변시가 움직임을 "변화 이벤트"로 잡는다 → 거짓 알림 |
| KRDS primitive 계층(`--krds-*`, L0) | 2계층으로 충분. 간접층이 늘면 역할이 흐려진다 |
| 48~80px 섹션 리듬 | 관제 밀도 3단(조임 2~8 / 묶음 12 / 분리 16)으로 |
| `font-display`·`font-mono` 별칭 | 값이 같은 간접층은 혼란만 준다 |

## 무엇을 새로 만들었나
- **초록 예산제** — 브랜드 픽셀 화면당 ≤1%. 허용 6가지 / 금지 목록 명문화([02](./02-brand-color-roles.md)).
- **브랜드 3단 분화** — `accent` / `accent-line` / `accent-ink`를 대비 문턱(3:1 / 4.5:1)으로 파생.
- **색+형태+단어 3중 부호화** — `StatusIndicator`(●/○) · `CapacityBadge`(채운 면/점선).
- **임베드 액자화** — Grafana 캔버스와 면 명도를 계단으로 맞춤([04 §2](./04-patterns.md)).
- **대비를 토큰 정의 시점에 계산해 주석에 못 박음** — 나중에 재는 게 아니라 정의할 때 정한다.

# 전환 과정에서 드러난 실제 결함 3건

> v3는 리스킨이 아니었다. 무채색화를 시도하자 **v2가 감추고 있던 버그가 노출**됐다.
> 아래 3건은 "디자인 취향"이 아니라 **고쳐야 했던 결함**이다.

## 결함 ① 포커스 링이 WCAG 1.4.11 미달이었다 (심각)

**증상.** v2는 `--color-brand = #38B38D`(브랜드 원색)를 포커스 링에 직접 꽂았다.
KRDS의 더블 링 구조는 그대로 가져왔으므로 코드는 "규격을 지킨 것처럼" 보였다.

**실측.**
| 조합 | 대비 | 판정 |
|---|---|---|
| `#38B38D` on `#FFFFFF` | **2.62:1** | ❌ 비텍스트/UI 최소 **3:1 미달** |
| `#38B38D` on `#F1F3F6` | 2.36:1 | ❌ |

즉 **키보드 사용자에게 포커스가 사실상 안 보였다.** 밝은 청록/민트 계열의 구조적 문제다
(초록은 상대휘도 계수 0.7152로 가장 크게 계산된다). 아무도 몇 달간 눈치채지 못했다 —
"브랜드 색을 썼으니 됐다"고 생각했기 때문이다.

**해결.**
1. 브랜드를 대비 문턱으로 **3단 분화**: `accent`(원색, 다크 전용) / `accent-line #2E9B7B`(**3.45:1**) /
   `accent-ink #1F7A61`(**5.23:1**).
2. 포커스 링을 `accent-line`으로 교체.
3. 더블 링을 **대비 보장 장치로 재해석** — 내부 2px `surface` 밴드가 링의 판정 배경을 흰 면으로 고정해
   3.45:1을 보증한다(밴드 없이 `surface-2` 위에 놓이면 3.10:1까지 하락).
4. 다크에서는 `accent-line = #38B38D`(6.78:1)로 되돌린다 — 어두운 면에서는 원색이 통과한다.

**교훈.** **브랜드 색은 hex 하나가 아니라 "대비 문턱으로 갈라진 3단"이다.**
이식 절차를 [02 §6](./02-brand-color-roles.md)에 8단계로 못 박았다.

## 결함 ② `font-medium`/`font-semibold`가 실파일 없이 합성되고 있었다

**증상.** v2 [01]은 "물리 폰트는 400·700만"이라 적고, 코드는 `font-medium`(500)·`font-semibold`(600)을
관행적으로 쓰고 있었다. v2 changelog에는 "500/600은 브라우저 synthetic weight — **미세한 렌더 차는 허용**"이라
적혀 있었다. 즉 **알면서 넘어간 상태**였다.

**왜 v3에서 결함이 됐나.** v2는 위계를 **크기**로 만들었으므로(17 → 19 → 24 → 32) 굵기가 조금 뭉개져도
티가 안 났다. v3는 **위계를 굵기로 만든다.** 400/500/600이 서로 구분되지 않으면 위계 자체가 사라진다.
게다가 합성 굵기는 한글에서 특히 나쁘다 — 자소가 밀집한 "쁘·쫒·괜" 같은 글자에서 획이 뭉개진다.

**해결.** PretendardGOV 릴리스에서 **Medium·SemiBold 실파일을 추가**해 400/500/600/700 4종을 로딩
(`app/fonts.ts`). 동시에 굵기 규약을 3단으로 정리하고 **700은 지양**으로 내렸다
— 실파일이 갖춰지자 400/500/600만으로 충분한 위계가 나왔기 때문이다.

**교훈.** "합성 굵기 허용"은 **크기로 위계를 만들 때만** 성립하는 타협이다.
굵기로 위계를 만드는 시스템에서는 실파일이 요건이다.

## 결함 ③ 무채색화하자 "정상"과 "수집 없음"의 구분이 소실됐다 (자초한 회귀)

**증상.** 원칙 2(유채색은 문제에만)를 적용해 `success` 초록을 걷어내자:
- `up`(정상) → `ink-faint` 회색 dot
- `no-data`(수집 없음) → `neutral` 회색 dot

**둘이 완전히 같아졌다.** 마찬가지로 `free`(여유)와 `unknown`(판정불가)도 둘 다 무채색이 되어 구분이 사라졌다.

**왜 심각한가.** 이건 미관 문제가 아니라 **제품 정직성 위반**이다:
- `unknown`이 `free`로 보이면 → "여유 있다"는 **거짓 안심** → 이미 가득 찬 GPU에 작업을 올린다.
- `no-data`가 `up`으로 보이면 → 죽은 수집기를 **정상으로 오인**한다.
- (반대로 `down`으로 보이면 거짓 경보로 야간 호출이 나간다.)

KEIwi 헌장의 "모르면 모른다고 한다" 원칙이 **시각 표현 층에서 깨진** 것이다.

**해결 — 색이 잃은 자리를 형태로 메운다.** 은유를 하나로 통일했다:
**속이 찼다 = 값이 있다 / 속이 비었다 = 값이 없다.**

| 축 | 값 있음 | 값 없음 |
|---|---|---|
| 노드 상태 | 정상 **● 채운 원** | 수집 없음 **○ 빈 원**(1.5px 링) |
| 여유 등급 | 여유 **채운 면**(surface-2) | 판정불가 **점선 테두리 + 투명 배경** |
| 임베드/패널 | 연결됨 실선 액자 | 미연결 **점선 액자** |

여기에 단어가 항상 병기되어 **색 + 형태 + 단어 3중**이 완성된다.
`status-indicator.tsx` / `capacity-badge.tsx` 주석에 이 근거를 남겨 "회색이니 통일하자"는 미래의
정리 시도를 막았다.

**교훈.** **원칙 2(유채색은 문제에만)와 원칙 6(색 단독 금지)은 세트로만 적용할 수 있다.**
색을 걷어내는 리팩터링은 반드시 **형태 부호화를 먼저 설계한 뒤** 진행해야 한다.
검증법: 그레이스케일 스크린샷에서 정보가 하나도 사라지지 않는지 본다.

# v2 — KRDS 이식 (2026-07-01 ~ 2026-07-24, **폐기**)

> 기록 보존용. 이 절의 규칙은 **더 이상 유효하지 않다.**

- 기반: KRDS(대한민국 디지털정부 디자인 시스템) 토큰·컴포넌트 규격 채택, 브랜드 색·로고만 자체 유지.
- 주요 배치: B0 토큰 정합(브랜드 초록 원복·더블 링 도입) → B0.5 Overview 크래프트(라인형 탭) →
  B0.7 규격 감사(반경 10px 통일·배지 4px·컨트롤 40px) → B0.8 콘텐츠 우선 레이아웃 →
  B0.9 로그 워크벤치 v2.
- v2가 남긴 **유효한 유산**(v3가 계승):
  - 더블 링 포커스 구조 (단, 색을 `accent-line`으로 교정 — 결함 ①)
  - "콘텐츠 우선 ≥60%" 관제 밀도 예외 → v3의 부속 규칙으로 승격
  - 정직성 3분법(정상 ≠ 다운 ≠ 데이터 없음) → v3에서 형태 부호화로 강화
  - Pretendard GOV 서체 (단, 실파일 4종으로 보강 — 결함 ②)
  - 정부 마스트헤드/기관 식별자 미채택 판단(내부 콘솔에는 허위 표기)
- v2가 남긴 **폐기된 것**: 17px 본문 · 32/40px 헤딩 · 요소별 반경 · 카드 그림자 · hover 리프트 ·
  success/info 색 계열 · KRDS primitive 계층.
