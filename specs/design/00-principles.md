# 00 · 디자인 원칙

> KRDS `outline_01`/`index`/`style_01`에서 도출. 모든 결정의 상위 기준.

## 4대 원칙
1. **일관성 (Consistency)** — 모든 화면에서 같은 컴포넌트·같은 토큰·같은 위치. 크롬(헤더/내비/푸터)·상태 표현·간격 리듬을 통일해 신뢰를 만든다. "이 화면만 특별하게"를 지양.
2. **디지털 포용 (Digital Inclusion)** — 모두가 동등하게 접근. WCAG/KWCAG **AA**를 기본선으로, 큰 본문(17px)·고대비 모드·색 단독 의미전달 금지.
3. **사용자 중심 / 여정 기반 (User-centered)** — 화면 단위가 아니라 사용자 여정(방문→탐색→로그인→신청→확인) 단위로 패턴을 조직.
4. **접근성은 타협 불가 (Accessibility is a hard requirement)** — 상시 가시 포커스·완전 키보드 조작·시맨틱 마크업은 옵션이 아니라 요건.

## 이 원칙이 UI에 강제하는 것
- **상태는 색+단어+(아이콘)**. "정상"은 초록 점 + "정상" 텍스트. 초록만으로 끝내지 않는다.
- **위계는 크기·굵기·간격으로**. 색으로 위계를 만들지 않는다(색은 의미/상태 전용).
- **밀도보다 판독성**. 관제 콘솔이라도 본문 17px·줄간격 1.5·충분한 여백을 우선.
- **예측 가능성**. 같은 동작은 같은 컴포넌트·같은 위치. 신규 위젯을 함부로 만들지 않고 `03-components`의 규격을 재사용.
- **정직성**. 데이터 없음 ≠ 정상 ≠ 장애. 불확실은 "판정불가"로 표기(거짓 안심 금지).

## 관제/대시보드 맥락 보정 — 관제(NOC) 밀도 예외
> 2026-07-03 명문화([07 모호점 ③](./07-changelog.md) 해소). 적용 범위 = 상시 모니터링 화면(Overview·현재신호 등 관제 화면). 일반 문서/설정 화면은 표준 규격을 따른다.

- 정보 밀도가 필요한 표/목록은 KRDS 기본 여백(PC 48/80px)을 축소 적용한다.
- 시계열 그래프는 전문 도구(Grafana 등) 임베드를 권장 — 네이티브 차트 재구현은 유지비가 크다(프로젝트 헌장에 따름).

### 허용되는 축소
- **페이지 제목(H1) 24px**(표준 32 — [01 heading-large](./01-foundations.md)). heading-medium 스케일 준용, 굵기 700 유지.
- **섹션 헤더 생략 가능**: 내용이 자명한 섹션(예: 임베드 대시보드 영역)은 시각 헤더를 생략하고 **`aria-label`(또는 sr-only 헤딩)로 시맨틱만 유지**. 시맨틱까지 없애는 것은 불가.
- **카드/스트립 패딩 8~12px**(표준 16~24 — [03 Card](./03-components.md)). 위계 요소(제목·상태·배지)는 유지.

### 콘텐츠 우선 원칙 (Content-first)
관제 화면의 주인공은 **주 콘텐츠(임베드·데이터 영역)** — 데스크톱 뷰포트의 **≥60%**를 차지해야 한다. 크롬(헤더·노드 스트립·탭·툴바)은 보조이며, 주 콘텐츠가 이 기준에 못 미치면 **크롬을 줄인다**(스트립 슬림화·헤더 생략·툴바 흡수). 크롬을 위해 콘텐츠를 줄이지 않는다.

### 불축소 항목(재확인) — 밀도 예외와 무관하게 유지
- **본문 크기 17px** · **줄간격 1.5** · **포커스 가시성**(더블 링, [01](./01-foundations.md)) · **색+단어 병기** · **터치 타깃 ≥44px**.
