# 00 · 디자인 원칙

> KRDS `outline_01`/`index`/`style_01`에서 도출. 모든 결정의 상위 기준.

## 4대 원칙
1. **일관성 (Consistency)** — 모든 화면에서 같은 컴포넌트·같은 토큰·같은 위치. 크롬(헤더/내비/푸터)·상태 표현·간격 리듬을 통일해 신뢰를 만든다. "이 화면만 특별하게"를 지양.
2. **디지털 포용 (Digital Inclusion)** — 모두가 동등하게 접근. WCAG/KWCAG **AA**를 기본선으로, 큰 본문(17px)·고대비 모드·색 단독 의미전달 금지.
3. **사용자 중심 / 여정 기반 (User-centered)** — 화면 단위가 아니라 사용자 여정(방문→탐색→로그인→신청→확인) 단위로 패턴을 조직.
4. **접근성은 타협 불가 (Accessibility is a hard requirement)** — 상시 가시 포커스·완전 키보드 조작·시맨틱 마크업은 옵션이 아니라 요건.

## 이 원칙이 UI에 강제하는 것
- **상태는 색+단어+(아이콘)**. "정상"은 초록 점 + "정상" 텍스트. 초록만으로 끝내지 않는다.
- **위계는 크기·굵기·간격으로**. 색으로 위계를 만들지 않는다(색은 의미/상태 전용).
- **밀도보다 판독성**. 관제 콘솔이라도 본문 17px·줄간격 1.5·충분한 여백을 우선.
- **예측 가능성**. 같은 동작은 같은 컴포넌트·같은 위치. 신규 위젯을 함부로 만들지 않고 `03-components`의 규격을 재사용.
- **정직성**. 데이터 없음 ≠ 정상 ≠ 장애. 불확실은 "판정불가"로 표기(거짓 안심 금지).

## 관제/대시보드 맥락 보정(선택)
- 정보 밀도가 필요한 표/목록은 KRDS 기본 여백(PC 48/80px)을 축소 적용하되, **본문 크기·줄간격·포커스·상태 규칙은 축소하지 않는다**.
- 시계열 그래프는 전문 도구(Grafana 등) 임베드를 권장 — 네이티브 차트 재구현은 유지비가 크다(프로젝트 헌장에 따름).
