# 00 · 디자인 원칙 (v3 Quiet Console)

> 모든 결정의 상위 기준. 아래 6개는 취향이 아니라 **관제 화면이라는 맥락에서 도출된 제약**이다.
> 판단이 갈리면 번호가 작은 원칙이 이긴다.

---

## 1. 침묵하는 콘솔 — "콘솔은 침묵하고 Grafana만 말한다"

**규칙.** 콘솔 크롬(헤더·사이드바·탭·카드·툴바)은 그 자체로 눈에 띄어서는 안 된다.
주의를 끌 권리는 데이터(임베드 대시보드·표·수치)에만 있다.

**왜.** 이 콘솔의 화면 면적 **약 2/3은 Grafana 임베드**다. Grafana는 자기 팔레트로 이미 색을 쓰고 있다
(빨강 알림, 노랑 경고, 시리즈별 다색 그래프). 콘솔 크롬이 여기에 자기 색을 더하면 두 색 체계가 경쟁해
사용자는 "어느 빨강이 진짜 문제인지" 매번 판별해야 한다. 크롬이 무채색이면 화면에서 유일한 유채색은
데이터가 만든 것이므로, **색이 곧 신호**가 된다.

**따르는 결정들.**
- 뉴트럴을 쿨(hue≈220, S 4~8%)로 잡았다 — Grafana가 쿨 계열이라, 웜그레이 크롬은 액자 경계에서
  색온도가 어긋나 "덧댄 UI"로 보인다.
- 라이트 `canvas #F7F8FA`는 Grafana 캔버스(#F4F5F5)보다 미세하게 밝고(1.03:1), 우리 카드와 Grafana 패널은
  둘 다 흰색이다 → 두 세계가 **한 장의 종이 위**에 놓인다. 다크는 부호가 뒤집혀 우리 canvas(#0C0D10)가
  Grafana 캔버스(#111217)보다 한 단 어둡다 → 임베드가 "뜬 면"이 된다.

**위반 예시.** 카드마다 색 헤더 스트립 / 사이드바 그라디언트 / 페이지마다 다른 액센트 테마 /
크롬 배경에 미세한 브랜드 워시.

## 2. 유채색은 "문제"에만 — 정상은 무채색이다 (**단, "상태"에 한해서다**)

**규칙.** 색상환의 유채색(빨강·주황)은 danger·warn에만 배정한다. **정상·성공·여유·완료는 무채색**
(`ink-muted` / `surface-2`)으로 표현한다.

**적용 범위 — 이 원칙은 "상태"에만 적용된다. "정체성"에는 적용되지 않는다.**
화면의 색은 두 개의 다른 질문에 답한다.

| | 답하는 질문 | 축 | 이 원칙 |
|---|---|---|---|
| **상태**(status) | "이거 괜찮은가" | 순서형 — 정상 < 주의 < 위험 | **적용된다.** 정상은 무채색 |
| **정체성**(identity) | "이건 어느 노드/모델인가" | 명목형 — 순서가 없다 | **적용되지 않는다.** 색을 준다 |

명목형 축에는 심각도가 없다. 따라서 "정상=무채색"이라는 명제 자체가 성립하지 않는다.
여기에 원칙 2를 적용하면 색이 정보를 **0비트** 운반하게 되고, 차트는 차트 기능을 잃는다.

**왜.** 5노드짜리 플릿에서 압도적 다수의 시간은 "전부 정상"이다. 정상을 초록으로 칠하면 화면의 기본 상태가
**초록 카펫**이 되고, 그 위에 뜬 빨강 하나가 카펫에 묻힌다. 정상이 회색이면 **화면에 색이 있다 = 볼 일이 있다**가
성립한다. 색은 희소해야 신호다.

부수 효과로 색각 이상(적록) 사용자에게 가장 위험한 조합인 **초록↔빨강 대비를 아예 만들지 않는다**.

**따르는 결정들.**
- `success-*` 토큰군을 **삭제**했다. 존재하면 누군가 쓴다.
- `info-*`도 삭제 — "정보성 파랑"은 대개 장식이었다.
- 경고색 `warn #F79009`는 흰 배경 대비 2.35:1이라 **단독으로는 판독 불가**다. 반드시 텍스트(`warn-ink`, 5.43:1)를
  동반해야 한다는 제약이 토큰 주석에 못 박혀 있다.

**위반 예시.** "정상 12대"를 초록 숫자로 / 성공 토스트 초록 배경 / 여유 배지 초록 tint /
진행률 100%를 초록으로.

**과잉 적용 예시 — 이것도 위반이다.** 시계열 차트의 노드별 선을 회색 계조로 / 모델별 막대를 단색으로 /
"어느 GPU인가"를 명도 차이로만 구분.

**근거 — 실제로 터진 실패 사례(2026-07-27, 커밋 `e61c23b` 기준).** 이 원칙을 시리즈 색에까지 적용해
v3 대시보드 16개 timeseries 패널을 `color: {"mode":"fixed"}` 또는 `{"mode":"shades"}` 단색으로 바꿨다.

- `system-v3` **CPU 추이** 노드 4선, **부하 평균** **12선**(4노드 × 1/5/15분)이 명도만 다른 회색이 됐다 —
  실측 인접 시리즈 대비 **1.01~1.10:1**, 구분 문턱 아래.
- `gpu-v3` **사용률 추이**, `model-workload-v3` **모델별 요청/토큰 처리율/지연 p95**는 `mode:"fixed"`라
  **전 시리즈가 같은 hex**(`#6E7583`)로 그려졌다.
- 남은 판별 수단은 범례를 하나씩 클릭해 보는 것뿐. **미관 저하가 아니라 기능 결함**이다
  ([07](./07-changelog.md) 결함 ④).

**교정 후 경계 — 정체성에 색을 주되 상태색을 침범하지 않는다** (상세 [02 §5](./02-brand-color-roles.md)).
- 시리즈 팔레트 6색: `#6E8BB8` `#38B38D` `#C08A5E` `#9B7BAF` `#7F9AA6` `#A08A7A` — 노드에 **항구 배정**.
- **저채도 강제**: 시리즈 S ≤ 52 vs 상태색 `danger` S74 · `warn` S94. 채도가 두 역할의 분리선이다.
- **빨강 `#D92D20`·주황 `#F79009`은 상태 전용 예약어** — 시리즈 팔레트에 넣지 않는다.
  빨간 선이 "이 노드가 고장"으로 오독되면 상태 체계 전체가 무너진다.
- 시리즈 색은 **데이터 영역(Grafana 패널 내부)에만** 존재한다. 콘솔 크롬에 쓰면 원칙 1 위반이다.
- 같은 노드의 하위 시리즈(마운트포인트·GPU 인덱스·1/5/15분)는 **색을 늘리지 말고 선 스타일**
  (실선/파선/점선)로 가른다. 4색 × 3스타일이 12색보다 잘 읽힌다.

**주의 — 이 원칙의 대가.** 정상을 무채색으로 만들면 **정상(무채색)과 "데이터 없음"(무채색)이 색으로
구분되지 않는다.** 이건 실제로 v3 전환 중 터진 결함이다([07](./07-changelog.md) 결함 ③).
해결은 원칙 6(형태 부호화)이며, 원칙 2를 적용할 때는 **반드시 원칙 6을 같이** 적용해야 한다.

## 3. 초록 예산제 — 브랜드색은 "지금 조작 중인 것"에만

**규칙.** 브랜드 초록은 **사용자의 현재 조작 지점**만 표시한다. 화면당 초록 픽셀 **≤ 1%**.

**허용 (이것이 전부)**
| 용도 | 형태 | 비고 |
|---|---|---|
| 포커스 링 | 2px 면 + 2px `accent-line` 더블 링 | 전역 `:focus-visible` |
| 사이드바 활성 항목 | 좌측 세로 룰 2px | 텍스트는 `ink` — 초록 글자 아님 |
| 활성 탭 | 하단 언더라인 2~3px | 텍스트는 `ink`+semibold |
| 선택된 카드 | 1px 보더(+선택 시 1px 링) | 배경 워시 금지 |
| primary 버튼 | 화면당 **최대 1개** | 페이지의 주 액션 하나 |
| 로고 | 원색 그대로 | 대비 규칙의 명시적 예외(장식) |

**금지**
- **링크 색** — 링크는 `text-ink-muted underline underline-offset-2`, hover `text-ink`.
  (밑줄이 이미 "클릭 가능"을 말한다. 문서 본문에 링크가 20개면 초록 20개가 흩어진다.)
- **정상 상태** — 원칙 2.
- **배지 배경** — tint 배경은 면적이 커서 예산을 즉시 초과한다.
- 아이콘 기본색 / 구분선 / 표 헤더 / 활성 아닌 것 전부.

**왜 "예산"인가.** 브랜드색의 기능은 "여기가 지금 당신이 만지는 곳"이라는 **단일 지시자**다. 화면에 초록이
두 곳 이상이면 지시 기능이 사라지고 그냥 테마색이 된다. 1%는 측정 가능한 상한이다 —
1440×900 화면에서 약 13,000px, 즉 2px 언더라인 3~4개 + 포커스 링 하나 정도.

**위반 예시.** 모든 섹션 제목 앞 초록 틱 / 모든 버튼이 primary / 초록 링크 / 초록 아이콘 세트 /
활성 탭 텍스트까지 초록(언더라인만으로 충분).

## 4. 그림자는 "떠 있어야만 하는 것"에만

**규칙.** `shadow-pop`은 **팝오버·드로어·모달**에만 쓴다. 카드·패널·액자·탭바·사이드바·표는 그림자 0.
분리는 **1px 보더 + 면 명도차**로 만든다.

**왜.** 그림자는 "이 요소는 다른 레이어에 있다"는 물리적 주장이다. 카드는 다른 레이어에 있지 않다 —
페이지에 박혀 있다. 카드마다 그림자를 주면 화면이 **일제히 5px 떠오르고**, 정작 진짜로 떠 있는 드롭다운이
같은 높이에 있어 레이어 구분이 사라진다. 그림자를 팝오버에만 남기면 그림자 자체가 "이건 임시로 뜬 것,
닫으면 사라진다"는 신호가 된다.

부수 효과: 그림자 없는 면은 명도차만으로 분리되므로 다크 모드에서 탁해지지 않는다
(다크에서 검은 그림자는 검은 배경에 안 보인다 → 다크 `shadow-pop`은 `0 0 0 1px border` 링을 겸한다).

**위반 예시.** 카드 hover 시 그림자 상승 / 사이드바 우측 그림자 / 고정 헤더 하단 그림자
(→ 보더 1px로) / 표 헤더 sticky 그림자.

## 5. 움직이지 않는다

**규칙.** hover·active에 `transform`(`translate`/`scale`)을 쓰지 않는다. 바뀌는 것은 **색뿐**이다:
`hover:border-border-strong hover:bg-surface-2`. 트랜지션은 `transition-colors` 수준(≤150ms).

**왜.** 관제 화면은 **상주 화면**이다. 사용자가 마우스를 옮기는 동안 카드가 들썩이면, 주변시(周邊視)는
그 움직임을 "변화 이벤트"로 잡는다. 실제 데이터가 갱신될 때의 움직임과 구별되지 않으므로
**거짓 알림**이 된다. 상용 대시보드 제품이 카드 리프트를 안 쓰는 이유가 이것이다.

또한 12~20개 노드 카드가 그리드에 깔린 화면에서 리프트 애니메이션은 리페인트 비용이 실제로 든다.

**예외.** 실제로 나타나고 사라지는 것(드로어 슬라이드, 팝오버 페이드)은 움직여도 된다 — 그 움직임이
"어디서 왔는지"를 설명하기 때문이다. 단 `prefers-reduced-motion`에서 전부 0.01ms로 무력화된다(전역 규칙).

**위반 예시.** `hover:-translate-y-0.5` / `hover:scale-105` / 로딩 스켈레톤의 펄스 애니메이션이
데이터 갱신처럼 보이는 경우 / 숫자 카운트업 애니메이션.

## 6. 색 단독 의미전달 금지 — 상태는 (색 + 형태 + 단어)

**규칙.** 모든 상태 표시는 **세 채널**로 부호화한다. 흑백 인쇄해도, 색각 이상이 있어도, 색을 못 보는
저조도 환경에서도 판별돼야 한다.

**왜.** 접근성 요건(WCAG 1.4.1)이기도 하지만, v3에서는 **원칙 2의 필수 짝**이다. 유채색을 문제에만 쓰면
무채색 상태가 여러 개 생기고, 그것들끼리는 색으로 구분이 안 된다. 형태가 그 자리를 메운다.

**구현된 부호화 (→ [03](./03-components.md))**
| 상태 | 색 | **형태** | 단어 |
|---|---|---|---|
| 정상 (up) | `ink-faint` | **● 채운 원** | "정상" |
| 다운 (down) | `danger` | ● 채운 원 | "다운" |
| 수집 없음 (no-data) | `ink-faint` | **○ 빈 원**(1.5px 링) | "수집 없음" |
| 여유 (free) | `ink-muted` | **채운 면**(surface-2) | "여유" |
| 바쁨 (busy) | `warn-ink` | 채운 면 + 보더 | "바쁨" |
| 가득 (full) | `danger-ink` | 채운 면 + 보더 | "가득" |
| 판정불가 (unknown) | `ink-subtle` | **점선 테두리 + 투명 배경** | "판정불가" |

은유가 일관된다: **속이 비었다 = 데이터가 없다.** 정상과 수집없음, 여유와 판정불가가 각각 채움/빔으로 갈린다.

**왜 이게 기능 요건인가.** "데이터 없음"이 "정상"으로 보이면 **거짓 안심**이고, "다운"으로 보이면
**거짓 경보**다. 모니터링 시스템의 정직성(모르면 모른다고 한다)이 시각 표현 층에서 깨지는 것이라
접근성 이전에 제품 결함이다.

**적용 범위 — 여기서도 "상태"와 "정체성"은 다르다.** 이 원칙(과 그 검증법인 그레이스케일 테스트)은
**상태 부호화**에 적용된다. 시리즈 색은 명도를 일부러 균질하게 맞췄으므로(L 46~58, 인접 대비 1.01~1.10:1)
**흑백에서 서로 안 보이는 것이 정상**이다. 정체성의 보조 채널은 명도가 아니라 **범례 라벨 + 선 스타일**이며,
이것이 원칙 6의 정체성판이다 — 색각 이상 2색형 시뮬레이션에서 현행 4노드 배정의 최악쌍 ΔE가 13.4(구분 문턱
약 15) 이므로 **시리즈도 색 단독으로는 부족하다**([02 §5.6](./02-brand-color-roles.md)).

**위반 예시.** 빨강/초록 점만 있고 라벨 없음 / 배경색만으로 행 상태 표시 / "○/●" 없이 회색 점 하나로
정상과 무응답을 둘 다 표현 / **범례를 끈 다중 시리즈 차트**.

## 부속 규칙 — 관제(NOC) 밀도

원칙이 아니라 위 6개를 적용할 때의 **치수 보정**이다.

- 단일행 UI 크롬(내비 항목·표 행·탭·칩·배지)은 **촘촘하게**. 여백은 정보를 밀어낸다.
- 본문 14px / 줄간격 1.5. 크기로 위계를 만들지 않으므로 최대 24px(페이지 제목 20px)면 충분하다.
- **콘텐츠 우선**: 주 콘텐츠(임베드·데이터 영역)가 데스크톱 뷰포트의 **≥ 60%**. 못 미치면 크롬을 줄인다.
  크롬을 위해 콘텐츠를 줄이지 않는다.
- **축소하지 않는 것**: 본문 14px 하한 · 줄간격 1.5 · 포커스 가시성 · 색+형태+단어 3중 부호화 ·
  터치 타깃(터치 지원 기기에서 ≥44px).
- 한글 하한 **11px**(`text-2xs`) — 10px에서는 "판정불가" 같은 자소 밀집 단어가 뭉갠다.
