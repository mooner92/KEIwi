# KRDS 기반 콘솔 디자인 시스템 — 이식형 스펙

> **목적 2가지.** ① 이 프로젝트(KEIwi 관제 콘솔)의 디자인을 앞으로도 **일관되게 고수**한다. ② 이 폴더를 **다른 프로젝트에 통째로 복사**해 같은 디자인 언어를 빠르게 재현한다.
>
> 기반 = **KRDS(Korea Design System, 대한민국 디지털정부 디자인 시스템)**. 컴포넌트·타이포·여백·상태 표현·접근성을 KRDS 규격으로 채택하되 **브랜드 색·로고는 각 프로젝트 자체 것**을 쓴다(§[02](./02-brand-color-roles.md)).
> 출처: KRDS 공식 레포 `github.com/KRDS-uiux/krds-uiux`(npm `krds-uiux`) + 가이드 `krds.go.kr` 심층 조사(2026-07-01).

## 이 스펙의 권위·범위
- 이 폴더(`specs/design/`)가 **디자인의 단일 진실원(SoT)**. 코드가 여기서 벗어나면 코드가 틀린 것.
- 프로젝트 헌장/ADR이 상위 권위일 경우 그와 충돌하지 않는 선에서 적용(예: KEIwi는 "차트=Grafana 임베드, 재구현 금지" → 이 스펙은 크롬/컴포넌트에만 적용).
- 이 폴더는 **프레임워크 중립**을 지향한다: `00`~`05`는 값·규칙(px/hex/상태)만 담아 어떤 스택에도 이식 가능. 스택 결합(Tailwind/Next/krds-uiux)은 `06`에만 격리.

## 새 프로젝트에 재사용하는 법 (요약)
1. 이 `specs/design/` 폴더를 복사한다.
2. `06-implementation.md`대로 `krds-uiux` 설치 + Pretendard GOV `@font-face` + 3계층 토큰(primitive→semantic→component) 배선.
3. `02`의 브랜드 규칙대로 **자기 브랜드 램프**만 `--color-brand`/포커스 링에 꽂는다. 뉴트럴·시맨틱·컴포넌트는 `01`/`03` 그대로.
4. `03` 컴포넌트 규격대로 UI 구현(값 준수). `05` 접근성 필수 항목 통과.
5. `06`의 검증(Playwright 라이트/다크·no-raw-hex·대비)으로 규격 준수 확인. `07`에 프로젝트 변경 이력 기록.

## 핵심 불변식 (어느 프로젝트에서든)
- **브랜드 색·로고는 자체 것.** KRDS 정부 블루(#256ef4)·KRDS 로고를 그대로 쓰지 않는다.
- **색 단독으로 의미 전달 금지** — 항상 텍스트/아이콘 병기.
- **포커스는 상시 가시**(더블 링). 제거 금지.
- **본문 17px·줄간격 1.5·폰트 굵기 400/700**.
- **토큰만 사용**(컴포넌트에 raw hex 금지). 값은 토큰 계층에만.
- **요소별 반경 고정**: 버튼/입력 6 · 카드 10 · 칩/태그/배지 4 · 인디케이터 2 · 배너 12(px).
