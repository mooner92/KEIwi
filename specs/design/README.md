# KEIwi 디자인 시스템 v3 — 정적(靜的) Quiet Console

> **한 문장 정체성: 콘솔은 침묵하고 Grafana만 말한다.**
>
> 관제 화면의 주인공은 데이터다. 크롬(껍데기)이 색·그림자·움직임으로 주의를 끌면 그만큼 데이터를 못 본다.
> v3는 색과 그림자와 모션을 **걷어내고**, 위계를 계조(階調)와 굵기로만 만든다. 유채색은 "문제"에만 남긴다.

## 이 스펙의 권위·범위
- 이 폴더(`specs/design/`)가 **디자인의 단일 진실원(SoT)**이다. 코드가 여기서 벗어나면 코드가 틀린 것.
- 단, **토큰의 값 자체**는 `apps/console/src/app/globals.css`가 원본이다. 이 문서의 표는 그 파일에서 옮겨온
  것이며, 값이 어긋나면 CSS가 맞고 문서가 틀린 것으로 본다. **값은 CSS에, 이유는 여기에.**
- 프로젝트 헌장/ADR이 상위 권위다. KEIwi의 경우 "차트=Grafana 임베드, 재구현 금지"(헌장 §2 / ADR-0002)가
  이 스펙보다 위이며, 실제로 v3의 원칙 1은 그 제약을 디자인 언어로 번역한 것이다.
- `00`~`05`는 **프레임워크 중립**(값·규칙만). 스택 결합(Tailwind v4 / Next.js)은 `06`에만 격리.

## v3가 v2(KRDS 기반)와 다른 점 — 요약
| | v2 (KRDS 이식) | **v3 (Quiet Console)** |
|---|---|---|
| 기반 | 대한민국 정부 디자인시스템 규격 채택 | **폐기.** 서체만 존치 |
| 본문 | 17px | **14px** (−18%) |
| 위계 | 크기(40/32/24/19/17) | **굵기 + 잉크 계조** (최대 24px) |
| 반경 | 요소별 2/4/6/10/12 제각각 | **4 / 6 / 8 / full** — 8px가 상한 |
| 그림자 | 카드 sm · hover md | **카드 0.** 팝오버·드로어·모달만 |
| "정상" 상태 | 초록(success-50) | **무채색**(ink-muted) — 유채색은 문제에만 |
| 브랜드 초록 | 링크·활성·성공·포커스 어디에나 | **초록 예산제** — 화면당 초록 픽셀 ≤ 1% |
| hover | `-translate-y-0.5` + 그림자 상승 | **움직이지 않는다.** 색만 바뀐다 |
| 링크 | 파란색(info) | `ink-muted` + 밑줄 |

## 왜 KRDS를 버렸고, 왜 서체만 남겼나
KRDS는 **대민 서비스**(불특정 다수·저빈도 방문·낮은 학습량)를 위한 규격이다. 17px 본문·큰 헤딩·넉넉한 여백은
"처음 온 사람이 실수 없이 신청을 마치게" 하는 데 최적화돼 있다.
관제 콘솔은 정반대다 — **소수·상주·고학습**. 한 화면에 최대한의 사실을, 스크롤 없이, 매일 본다.
KRDS 규격을 그대로 쓰면 크롬이 화면의 절반을 먹고 정작 임베드된 대시보드가 밀려난다.

남긴 것은 **Pretendard GOV 서체 하나**다. 이유는 규격 준수가 아니라 품질이다:
1. 국문 관제 화면용 대체재가 마땅치 않다(자소 밀집 구간에서 무너지지 않는 한글 산세리프).
2. **tabular 숫자 품질** — IP·바이트·퍼센트가 초당 갱신되는 화면에서 자리수가 흔들리지 않아야 한다.
3. 400/500/600/700 **실파일 4종**을 배포한다 → v3의 "위계는 굵기로" 원칙이 합성(faux) 없이 성립한다.
   (v2 시절 500/600을 실파일 없이 쓰던 결함 → [07](./07-changelog.md) 결함 ②)

## 다른 프로젝트에 이식하는 법
1. 이 폴더를 통째로 복사한다.
2. `06`대로 `@theme` 토큰을 배선한다. **[01](./01-foundations.md)의 뉴트럴·상태 값은 그대로 복붙**해도 된다
   (특정 브랜드에 묶여 있지 않다).
3. **브랜드 색만 [02](./02-brand-color-roles.md)의 절차로 다시 계산한다.** 원색 하나를 정한 뒤
   흰 배경 대비를 재고, 3:1 / 4.5:1 두 문턱을 못 넘는 만큼 어두운 파생색을 만든다. 이 계산을 건너뛰면
   포커스 링이 WCAG 1.4.11에 걸린다(v3가 실제로 고친 결함 ①).
4. `03`의 컴포넌트 규격으로 UI를 구현한다. 상태 표시는 반드시 **색+형태+단어** 3중.
5. `06`의 게이트(typecheck · no-raw-hex · Playwright 라이트/다크)를 CI에 건다. `07`에 프로젝트 이력을 쓴다.

## 핵심 불변식 (어느 프로젝트에서든 깨지 말 것)
1. **정상·성공·여유는 무채색.** 유채색은 문제(danger/warn)에만 쓴다.
   **단 이 규칙은 "상태"에만 적용된다** — "어느 노드/모델인가"(정체성)는 범주 축이라 색을 준다(저채도
   `series-1~6`). 상태 규칙을 시리즈 색에 적용하면 다중 시계열이 판독 불가가 된다([07](./07-changelog.md) 결함 ④).
   빨강 `#D92D20`·주황 `#F79009`은 **상태 전용 예약어** — 시리즈 팔레트에 넣지 않는다.
2. **브랜드색은 "지금 조작 중인 것"에만.** 화면당 브랜드 픽셀 ≤ 1%. 링크·정상 상태·배지 배경에 금지.
3. **그림자는 실제로 떠 있는 것(팝오버·드로어·모달)에만.** 카드·패널·탭바·사이드바 그림자 = 0.
4. **hover에 `transform` 금지.** 색만 바뀐다.
5. **색 단독으로 의미를 전달하지 않는다.** 상태 = 색 + 형태 + 단어.
6. **컴포넌트 코드에 raw hex 금지.** 값은 토큰 계층에만(`check:no-raw-hex`가 강제).
7. **반경 상한 8px.** 4(배지) / 6(컨트롤) / 8(면) / full(dot·토글) 넷뿐.
8. **`ink-faint`는 비텍스트 전용.** 대비 2.63:1이라 텍스트에 쓰면 AA 위반.
