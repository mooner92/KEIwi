# KEIwi 자동 조치 (Auto-Remediation) — 알림을 넘어 "어느 정도 해결까지"

> **한 문장: 지금 KEIwi는 알림에 원인·근거를 붙여 사람에게 넘긴다(진단). 이 스펙은 그 다음 한 칸 —
> "사람이 클릭하면 미리 검증된 조치가 실행되는" 데까지만 — 을 헌장을 깨지 않고 설계한다.**
>
> 사용자 요청은 "로컬 LLM이 공식 매뉴얼을 참조해 **어느 정도 해결까지 자동으로**"다. 인프라는 정답이
> 있는 문제가 많으니 될 것 같다는 직관은 옳다. **그러나 "자동 해결"이라는 말과 실제 성숙 제품이
> 하는 일 사이엔 큰 간극이 있다.** 이 문서는 그 간극을 정직하게 드러내고, KEIwi가 **안전하게 갈 수
> 있는 만큼**을 자율 사다리(L0~L4)로 못박는다.

- 작성 2026-08-04. 상태: **리서치 확정 · 스펙 초안 → 착수는 사용자 선택 + ADR-0026(신설 예정) 승인 후.**
- 권위: 헌장(§11 생성/적용 분리 · §12 라이브 직접수정 금지 · §I-1 온프레미스 · §13 시크릿 레포 밖 · §15 알림 노이즈 최소화 · §16 멱등성). **이 셋과 정면으로 긴장하는 요청이므로, 긴장의 해소를 §4에서 전면에 둔다.**
- 이 폴더가 "자동 조치"의 단일 진실원(SoT)이다. 코드가 여기서 벗어나면 코드가 틀린 것(§7).
- 앞선 결정과의 관계: 이 스펙은 [`sre-addons/aiops-beyond-chat.md`](../sre-addons/aiops-beyond-chat.md) 2-4(알림 조사 패키지)와 [`specs/assistant`](../assistant/spec.md)의 **"조사·제안까지"** 선을 이어받아, 그 위에 **"승인 실행"** 한 칸을 얹는 유일한 문서다. 진단·이상탐지·다이제스트는 그 문서들이 SoT이며 여기서 재설계하지 않는다.

## 1. 먼저, 업계가 실제로 하는 일 — "자동 해결"의 정직한 해부

"요즘 AX가 유행"이고 벤더들은 "auto-remediation", "self-healing", "autonomous AI SRE"를 판다.
**리서치 결과, 성숙 제품 전부가 실제로는 같은 구조다:**

> **LLM = 읽기전용 진단·제안(비결정론) / 실행 = 사람이 미리 작성한 결정론 런북 / 그 사이 = 사람 승인 게이트.**
> LLM에게 프로덕션 명령을 자유 실행시키는 상용 제품은 사실상 없다.

| 제품/연구 | 진단·조사 | 실제 조치 실행 | 어디서 멈추나 |
|---|---|---|---|
| **PagerDuty** SRE Agent + Runbook Automation (2025.10 GA) | LLM이 RCA·플레이북 **제안** | 사람이 사전 작성한 **결정론 Job**을 Automation Actions로 호출 | "추천 → 사람 승인 후 실행". LLM은 어떤 런북을 부를지 고를 뿐 |
| **Datadog** Bits AI SRE (2025.12 GA) | 조사는 **완전 자율**(멀티스텝 가설·쿼리) | 추천 액션은 **원클릭(사람)**, 코드 원인은 **PR 제안** | 프로덕션 변경 자동 실행 없음 |
| **Dynatrace** Davis(Causal)+CoPilot | 인과분석은 **결정론 로직**이 근본원인 특정 | 사전 구성 **Workflow**가 실행 | LLM은 요약·제안만, 실행은 결정론 |
| **incident.io** AI SRE | Slack에서 멀티에이전트 병렬 조사 | 현재 **제안 중심**, 실행은 로드맵 | 사람 개입 전제 |
| **Rootly** AI SRE | 조사·근본원인·초안 | **"모든 변경은 사람 서명 후"** | 4단계 성숙도(읽기→조언→승인→가드레일 자율)를 명시 |
| **Cleric** (2025.12 GA) | 자율 조사 + 신뢰도 점수 | **"입증된 문제유형에 한해 사전승인 액션"**(earned autonomy) | 신뢰도 게이팅, 임의 실행 아님 |
| **Resolve.ai** | 조사는 **샌드박스 읽기전용 CLI만** | 복구는 **PR 제안**, 실행은 사람 승인 | 진단 권한을 읽기전용으로 못박음 |
| **Traversal** | 인과 검색으로 breaking-change 격리(RCA 전용) | **조치 표방 안 함** | 사실상 진단만 |
| **HolmesGPT** (CNCF, 오픈소스) | ReAct + `fetch_runbook`으로 탐색 축소 | 변경툴은 **항상 사람 승인**, 임의 kubectl 차단 옵션 | "읽기=자동 / 변경=사람 승인" 고정 분리 |
| **k8sgpt-operator** (오픈소스) | analyzer 자동 탐지 | `riskThreshold`+similarity 게이팅 자동 patch | **롤백 미구현(TODO)** · 프로젝트 스스로 "프로덕션 부적합" 명시 → **반면교사** |

**결론: 우리가 벤치마크로 삼을 구조는 이미 정해져 있다.** PagerDuty·Datadog·Dynatrace·Rootly·Resolve가
수렴한 "제안=LLM / 실행=결정론+승인"은 KEIwi 헌장 §11(레포에 생성·사람이 적용)·§12(라이브 직접수정
금지)와 **충돌이 아니라 그 구현**이다. 우리는 이 패턴을 SaaS 없이 로컬(vLLM + OpenSearch + Ansible)로
재현한다.

## 2. 왜 "완전 자동"을 노리면 안 되는가 — 벤치마크가 말하는 것

"근본원인을 안다"와 "올바른 조치를 실행한다"는 다른 문제다. 최신 벤치마크가 그 간극을 수치로 보여준다.

| 근거 | 수치 | 함의 |
|---|---|---|
| IBM **ITBench-SRE** | 최상 에이전트 인시던트 **해결률 13.8%** | 프론티어 모델도 6건 중 1건 못 푼다 |
| **RAG 기반 RCA** 벤치 | 근본원인 정확도 **91.4~99.7%**인데 **유효 복구(recovery validity) 36.8~60.3%** | 원인은 맞혀도 조치는 절반이 틀린다 |
| 1,675 에이전트 런 분석 | **해석 단계 환각 71.2%** · 불완전 탐색 63.9% | 로그를 "정답"처럼 요약하고 곧장 조치로 넘어가면 잘못된 전제 위에 실행 |
| MS **AIOpsLab** (end-to-end) | 최고 에이전트 **성공률 29%**, GPT-3.5+Shell은 가장 빠르지만(19초) **성공 0%** | 탐지~완화 완전 자동은 최고 모델로도 1/3 미만 |
| Meta 실사용 RCA | 원인 top-5 정확도 **42%** | 세계 최고 인프라 팀도 "실행"이 아니라 "후보 좁히기"에 LLM을 쓴다 |
| **MicroRemed** (2025.11) | 다단계·정밀 파라미터 복구 오류율 "비지도 배포 금지 수준" | **단일·멱등·가역 조치만**, 다단계 자동복구는 금물 |
| ReAct RCA (MS, 2024) | 정확도 35%지만 **검색 강제 시 환각 4~6%** (무근거 40% 대비) | 근거번호 강제가 환각을 구조적으로 막는다(KEIwi가 이미 하는 것) |

**우리 모델은 프론티어가 아니다.** KEIwi `:8003` Qwen3-Coder-30B는 BFCL-v2 **76.63%**(Llama-3.3-70B
77.30%에 근접), 코드 태스크 well-formed 콜 **~96%**로 **"엄격 JSON 스키마가 주어진 단일 구조화
툴콜"엔 충분**하다. 그러나 다단계 오케스트레이션은 상위 3~5개 모델만 신뢰 범주이고, 파라미터 수가
신뢰를 보장하지도 않는다(Mistral Small 24B 툴콜 pass 42.5%). → **30B에겐 "단일 조치 제안 + 스키마
강제"는 맡기되 "다단계 자율 복구"는 맡기지 않는다.** 로컬 30B는 프론티어보다 낮으므로 임계를 더
보수적으로.

> STCLab 실증(HolmesGPT): 동일 알림·동일 모델이 **런북 있을 때 4.6/5 vs 없을 때 3.6/5**, 낭비 툴콜
> **16→2회**. 그리고 약 **40%가 "진단이 명백해 사람이 수동 조치"로 자연 해결**됐다. 이 40%가 우리가
> 현실적으로 노릴 상한이다 — "런북이 모델보다 중요하다."

## 3. 자율 수준 스펙트럼 — 이 프로젝트의 공용 언어 (L0~L4)

업계 성숙도 모델(TM Forum ANL L0~L5 · 6단계 self-healing · Rootly 4단계 · Cleric earned-autonomy)을
KEIwi 5노드·1인·로컬 30B·egress0 제약에 맞춰 **5칸으로 재정의**한다. **"자동 해결" 요청은 이 사다리에서
한두 칸 올라가는 것으로 안전하게 번역된다 — 점프가 아니다.**

| 레벨 | 이름 | LLM 권한 | 실행 주체 | 헌장 | KEIwi 판정 |
|---|---|---|---|---|---|
| **L0** | 진단만(현행) | 읽기전용 · 근거번호 | 없음(사람이 다 함) | §11/§12 그대로 | **라이브** — assistant·alert-enrichment |
| **L1** | 조치 **제안** | 인시던트 분류 → 카탈로그 런북 **선택** + 명령 블록 게시 | **사람이 복붙** | §11/§12 그대로(생성만) | **1차 목표** — 가장 안전·즉시 |
| **L2** | **승인 후 실행** | 위와 동일(제안) | 사람이 **Slack 버튼/[server]** 클릭 → **결정론 워커** 실행 | 클릭=§11 "사람이 적용" | **2차 목표** — ADR-0026(신설 예정) |
| **L3** | 사전승인 **안전조치 자동** | 위와 동일(선택만) | 4조건 통과 화이트리스트만 dry-run→apply, 결정론 워커 | **개정 아닌 신규 ADR로 정식 결정** | **조건부 · ADR-0027(신설 예정)** |
| **L4** | 완전 자동 | 자유 진단→조치 | LLM이 라이브에 직접 | §11/§12 **위배** | **가지 않는다**(§ 근거) |

**각 레벨에서 무엇이 가능/금지인가:**

- **L0 (현행, 라이브).** 알림에 원인 후보·증거 스냅샷·근거번호를 붙여 사람에게 넘긴다. 상태를 바꾸지 않는다. → `specs/assistant`, `sre-addons/aiops-beyond-chat.md` 2-2/2-4가 SoT.
- **L1 (제안).** vLLM이 인시던트를 **유한 카테고리로 분류**하고 `docs/runbooks/`에서 **이름 붙은 런북을 고른다**. 제안 답글에 근거번호 + "실행하려면 이 명령" 코드블록을 붙인다. **명령 문자열을 생성하지도, 실행하지도 않는다.** 매뉴얼에 없으면 "매뉴얼 없음 — 진단만" 반환. → 헌장 무충돌(순수 생성).
- **L2 (승인 실행).** L1 제안 옆에 dry-run diff와 **[승인]/[거부] 버튼**을 둔다. 사람이 승인하면 **결정론 최소권한 워커**가 사전 검증된 런북을 실행하고 결과를 스레드에 회신. **사람의 클릭 1회가 헌장이 말하는 "사람이 적용"이다** — 그래서 개정 없이 ADR로 수용 가능.
- **L3 (사전승인 안전조치 자동).** "정답형·저위험·멱등·롤백가능" **4조건을 모두** 만족하는 극소수 조치만, 그것도 dry-run→plan→apply + blast radius 1노드 + circuit breaker + 자동 rollback으로. **이건 결정론 워커가 사람 클릭 없이 라이브를 바꾸므로 진짜 새 결정이다 — 반드시 별도 ADR-0027(신설 예정)로 정식화**하고, 후보별로 "L2에서 N회 무사고" 이력이 쌓인 뒤에만 승격(earned autonomy).
- **L4 (완전 자동).** **가지 않는다.** 근거: ①벤치마크(§2)상 로컬 30B로 완전 자동은 실증적으로 위험. ②5노드=1노드가 플릿의 20%라 한 번의 오조치 폭발반경이 곧 전 함대. ③1인 운영이라 잡아줄 2번째 엔지니어가 없다. ④헌장 §11/§12 정면 위배. **못 가는 게 아니라 안 가는 것이 올바른 설계 결정이다.**

## 4. 헌장과의 긴장 — 숨기지 않고 여기서 정면으로 푼다

사용자 요청("자동 해결")은 §11(에이전트 생성·사람 적용)·§12(라이브 직접수정 금지)와 **정면으로
긴장한다.** 이 스펙의 존재 이유가 이 긴장을 정직하게 푸는 것이다.

| # | 긴장 | 헌장 조항 | 해소 |
|---|---|---|---|
| C1 | LLM이 "조치까지" 하면 §11(적용은 사람) 위배 | §11 | **L1/L2는 위배 아님**: LLM은 끝까지 **제안·선택만** 하고, 적용을 트리거하는 것은 **사람의 클릭**이다. 결정론 워커가 실행하되 사람 승인 게이트 뒤에서만 |
| C2 | L3(사전승인 자동)은 사람 클릭 없이 라이브를 바꾼다 | §11/§12 | **개정으로 뭉개지 않는다.** L3는 **별도 ADR-0027(신설 예정)로 정식 결정**하고, 헌장에 "L3 예외" 문구를 ADR로 추가. 4조건+가드레일+earned-autonomy가 그 예외의 경계 |
| C3 | Slack 웹훅 = egress(승인·회신 채널) | §I-1 온프레미스 | 이미 alerting이 연 **egress 예외 1건**(ADR-0018 계획)에 편승. **나가는 필드 화이트리스트**(alertname/severity/node/runbook-id만) 강제. 승인이 Slack에 종속되므로 **CLI 폴백 승인 경로** 필수 |
| C4 | 실행 워커가 관제 대상 노드에 있으면 장애 시 승인·실행 불가 | 안전 | **control plane 아웃오브밴드**: data05 터널 관리 런북을 data05에서 실행 금지. 승인/kill 경로가 관제 대상에 의존하지 않게(Facebook 2021 교훈) |
| C5 | 자동 실행 워커는 root 권한이 생긴다 | §13/§15 | 워커는 **화이트리스트 런북만** 실행하는 최소권한. LLM은 워커에 **런북 id + 검증된 인자**만 넘김(명령 문자열 금지). 불변 감사로그 |

| 필요한 것 | 재사용할 기존 자산 | 신규 |
|---|---|---|
| 알림 → 스레드 파이프 | alerting Slack contact point(ADR-0018 계획) · `sre-addons/aiops-beyond-chat.md` 2-4 조사 패키지 | 스레드에 [승인] 버튼 계층만 |
| 근거 강제 RAG | `specs/assistant`의 OpenSearch **BM25 + 근거번호 검증기**(서버검증 인용) | 런북 코퍼스 색인 + 근거-조치 정합 검증기 |

## 7. 이 스펙이 하지 않는 것 (스코프 아웃 — 암묵 누락 금지)

- **L4 완전 자동/무인 self-healing** — §3 근거로 로드맵에서 **명시적 제외**. "AX 유행"에 밀려 넣지 않는다.
- **LLM의 자유형 명령 생성·실행** — LLM은 카탈로그의 **이름 붙은 런북을 선택만**. 명령 문자열을 짓거나 실행하지 않는다(§C5, HolmesGPT도 임의 kubectl 차단).
- **자율 ReAct 다단계 루프** — 로컬 30B 한계(§2). 단일 구조화 제안만.
- **비가역·고blast 조치의 자동화** — 재부팅(드라이버 mismatch) · 디스크 물리교체(SMART) · 커널/드라이버 변경 · 데이터 손실 위험 종료 · **연구자 프로세스 kill**(data01 Jupyter 291GB 사례)은 신뢰도와 무관하게 **영영 사람 전용**(Tier0).
- **진단·이상탐지·다이제스트 재설계** — `assistant`·`aiops-beyond-chat.md`가 SoT. 여기선 그 위의 "승인 실행"만.
- **알림 규칙 신설/임계 튜닝** — `specs/alerting`이 SoT. 여기선 그 규칙을 런북·티어에 **매핑**만.
- **자체 학습/파인튜닝 자동화 파이프라인** — few-shot + RAG로 시작(라벨 확보 부담, aiops 2-2 참조).
- **풀스택 OPA 정책엔진** — 5노드·1인엔 과잉. 리뷰된 allowlist YAML로 대체(§spec).
