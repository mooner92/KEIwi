# 로그 어시스턴트 (온프레미스 RAG) — Spec (WHAT + WHY)

- 상태: 초안 (착수 2026-06-29)
- 권위: [`Constitution.md`](../../Constitution.md) 종속. 충돌 시 헌장이 이긴다.
- 원칙: **Spec이 진실의 원천**(헌장 §7). 기술스택·프롬프트·검색식은 → [plan.md](./plan.md).
- 로드맵: 새 마일스톤이 아니라 **M1/M2 고도화**([ADR-0012](../../docs/decisions/0012-roadmap-m3-m4-pivot.md))로 묶는다. 보류된 M4(장애)·M5(알림)를 **무겁지 않게 흡수**(엔터프라이즈 incident board 안 만듦).
- 근거: 설계 워크플로(2026-06-29) 비평이 깎아낸 MVP. 관련 [plan](./plan.md)·[ADR-0014](../../docs/decisions/0014-log-assistant.md).

> 무엇·왜만. 어떻게(BFF·vLLM·OpenSearch 검색·인용검증)는 plan.md.

## 목적

운영자가 에러를 만났을 때, **콘솔에서 "이 에러 분석"을 누르면 로컬 LLM이 관련 로그를 근거(인용)와 함께 진단**하고, 기존 런북·Grafana로 연결한다. 신호 우선 로그 뷰(M2)가 "무엇이 일어났나"라면, 어시스턴트는 그 위의 **"왜·무엇을 보라"** 레이어.

- **WHY — 온프레미스 자원 활용(헌장 §I-1).** 이미 자체 GPU에 vLLM(Qwen3-Coder-30B 등)이 떠 있다. 외부 API 0으로 로그(OpenSearch)·메트릭(Prometheus)을 LLM에 묶을 수 있다 — 데이터 내부 유지(§13).
- **WHY — M4/M5 흡수.** 보류한 장애 추적·알림을, 정식 시스템 없이 "진단 + 기존 런북 연결 + 인시던트 지식화"로 더 가볍게 대체.
- **WHY — measure-first 단순성(헌장 §6).** 5서버 규모에 맞춰 **벡터DB·관계형DB·에이전트·자동적용을 도입하지 않는다**(가치 입증 전까지). 읽기 전용·근거 강제로 시작.

성공은 §수용 기준의 기계 검증으로 정의한다(헌장 §9) — **특히 "기존 /logs 대시보드를 실제로 이기는가"를 포함**.

## 범위 (in / out)

### In (MVP)
1. **에러 진입점** — 콘솔에 "현재 신호"(최근 error+warn top-N, OpenSearch 읽기전용) 얇은 뷰. 각 행 "분석" → 어시스턴트에 그 에러 컨텍스트(service·fleet_node·message·시간창) prefill. (Grafana iframe은 cross-origin이라 버튼 주입 불가 → 이 네이티브 진입점이 유일 경로.)
2. **읽기전용 RAG 질의** — 에러 컨텍스트로 OpenSearch에서 관련 로그를 검색(신호우선 필터·top-K·중복접기)해, **로컬 vLLM**이 진단을 생성.
3. **근거 강제** — 응답의 모든 주장은 **실제 검색된 로그(doc 식별자·시각·노드)를 인용**해야 한다. 근거 없는 주장·날조 인용은 표시하지 않는다(서버측 검증).
4. **연결(재구현 금지, §I-2)** — 상세 탐색은 기존 **/logs Grafana 딥링크**(같은 시간창·필터)로, 메트릭은 Overview 임베드로 위임. 어시스턴트는 그래프를 그리지 않는다.
5. **인시던트 지식 씨앗** — 기존 런북([rsyslog](../../docs/runbooks/rsyslog-omfile-flood.md))을 **표준 frontmatter**(증상·시그니처·detection_query·fix_kind)로 승격 → 다음 유사 에러 때 검색·연결.

### Out (비범위 — 가치 입증 후로 연기)
- **해결책(fix) 자동 생성** — 로그엔 해결책이 없다(환각 최고 위험). MVP는 진단·요약·**기존 런북 링크**까지만.
- **자동 적용**(시나리오 4) — 헌장 §11(사람 적용)·§15상 **강한 정당화 없이는 영구 보류**. 조치는 사람-PR 게이트.
- **능동 통보(M5)** · **벡터DB/임베딩** · **관계형 인시던트DB** · **tool-calling 에이전트** — 전부 measure-first 뒤(키워드/BM25·런북 frontmatter·git로 시작).
- **메트릭/로그 대시보드 재구현**(§I-2 — Grafana).

## 사용자 스토리

운영자 관점.

- **UA1 — 에러에서 바로 질의.** 콘솔에서 에러를 보고 ssh·grep 없이 "이거 분석"을 눌러 1차 진단을 받고 싶다.
- **UA2 — 근거를 본다.** 진단이 **어느 로그(노드·시각)에 근거**했는지 보고, 한 번에 그 로그(Grafana)로 가고 싶다(환각 불신).
- **UA3 — 전에 본 에러인가.** 같은 증상을 전에 어떻게 풀었는지(런북) 자동으로 연결받아 같은 삽질을 반복하지 않고 싶다.
- **UA4 — 데이터가 안 샌다.** 로그·질의가 외부로 안 나가고(로컬 vLLM), 시크릿이 프롬프트에 안 섞이길 바란다.
- **UA5 — 정직.** 어시스턴트가 모르면 지어내지 말고 "근거 없음"이라고 하길 바란다.

## 수용 기준 (기계 검증 가능)

- [ ] 콘솔 "현재 신호" 뷰에서 에러 행 "분석" → 어시스턴트에 컨텍스트가 prefill된다.
- [ ] 어시스턴트 응답의 인용은 **실제 검색셋에 존재하는 doc만**(서버측 대조 — 날조 인용 차단). 근거 없는 주장 비표시.
- [ ] 외부 egress **0** — Prometheus·OpenSearch·vLLM 호스트(내부)만 접촉.
- [ ] 프롬프트 조립 **전** 시크릿 스크럽(토큰/argv) — 로컬이라도 프롬프트에 시크릿 미혼입(§13).
- [ ] 검색 로그는 **데이터로 격리**(프롬프트 인젝션 불복) — 로그 본문의 지시를 따르지 않는다.
- [ ] **가치 베이스라인** — 시드 에러에 대해, 어시스턴트가 "사람이 그냥 /logs 본다" 대비 더 빠르게 원인 로그·런북에 도달함을 측정(배관이 아닌 가치).
- [ ] 콘솔은 OpenSearch/vLLM을 **읽기만**. KB 인덱스는 **사람이 머지한 런북에서만** 재빌드(draft 인덱싱 금지).
- [ ] 단일 콘솔(§I-2) — 상세 그래프는 Grafana 딥링크(어시스턴트는 재구현 안 함).
