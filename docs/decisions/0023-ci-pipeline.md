# 0023. CI 파이프라인: GitHub 호스티드 전용 + 게이트 레지스트리

- 상태: 채택 (2026-08-03)
- 관련: [specs/fleet-hardening/spec.md §5](../../specs/fleet-hardening/spec.md)(실행 스펙) · [docs/branching.md](../branching.md)(브랜치 보호) · [docs/testing.md](../testing.md)(격리 빌드·시각 QA) · 헌장 §9·§11·§12·§13·§I-1
- 번호: 0018~0021은 [hardware-ops README §5](../../specs/hardware-ops/README.md)가 예약했고 0022는 에러 트래킹이 쓴다 → **0023**.

## 맥락

헌장 §9는 "모든 spec의 acceptance criteria는 실행·검증 가능해야 하며 **CI가 강제한다**"고 선언한다. 그런데 `.github/workflows` 디렉터리 자체가 없었다(worktree·프로덕션 양쪽 확인). `docs/branching.md`는 이미 "Require status checks to pass — CI 초록일 때만 머지"를 규약한다. **강제 장치를 문서가 전제하는데 실체가 없었다.**

그 공백의 대가가 실측으로 남아 있다. 콘솔 시크릿 게이트는 **rc=1(히트 16행)인 채로** v0.1.0·v0.2.0 두 번의 태그를 통과했다. 히트 16건 중 14건이 오탐(XML 네임스페이스 URI·테스트 픽스처·JSDoc 예시·호스트 리터럴이 없는 템플릿 리터럴·공개 링크)이었고, 오탐이 일상이 되자 아무도 rc를 보지 않게 됐다. **게이트가 red인 것보다 나쁜 것은 red가 정상이 되는 것이다.**

동시에 그 게이트는 **진짜 시크릿을 하나도 탐지하지 못했다** — 규칙이 `https?://`로 시작하는 문자열만 봤기 때문에 개인키·Slack 토큰·GitHub 토큰·에러 트래커 DSN·터널 JWT는 전부 통과했다. 오탐과 미탐이 **같은 원인**(잘못된 추상화: "src 안의 모든 외부 URL 금지")에서 나왔다.

## 결정

### 1. GitHub 호스티드 러너 전용. self-hosted 러너를 두지 않는다

기각 이유 셋:
1. 러너를 data03/05에 두면 **연구 GPU 워크로드와 CPU·디스크를 경쟁**한다. 이 플릿의 존재 이유는 연구 잡이지 CI가 아니다.
2. 러너가 내부망 자격으로 라이브에 도달할 수 있게 되어 **§12(라이브 수정 금지)를 우회하는 경로**가 생긴다. 자동화가 사람의 승인 절차를 건너뛰는 통로가 되는 것이 이 레포에서 가장 피하고 싶은 형태다.
3. 관제 대상이 아닌 **새 상태저장 서비스**가 늘어난다.

실측으로 모든 게이트가 내부망 없이 통과하고, `next build`가 **환경변수 하나 없이 rc=0**이다. 레포가 PUBLIC이라 호스티드 러너 과금도 0이다.

**부수 효과가 오히려 본질이다**: 콘솔은 `apps/console/.next`를 **라이브로 서빙**하므로 data05에서는 build 게이트를 상시 돌릴 방법이 구조적으로 없었다(`docs/testing.md`). CI 도입의 가장 큰 실익은 "자동화"가 아니라 **라이브를 안 건드리고 빌드를 검증할 유일한 장소**가 생긴 것이다.

### 2. molecule을 도입하지 않는다 — ansible-lint + syntax-check + Jinja2 렌더 스모크로 대체

근거 4가지:
1. role 5개가 **전부 systemd 유닛을 설치**한다 → privileged 컨테이너 + systemd 이미지가 필요하다.
2. **타깃이 균질하지 않다.** `filebeat-xenial`이 별도로 존재하고 16.04는 2021 EOL이라 apt 저장소가 없다 → 컨테이너 프로비저닝이 네트워크 의존이고 플레이키해진다.
3. 실제 위험("템플릿 오렌더"·"태스크 문법 오류")의 대부분은 **초 단위 오프라인 검사**로 잡힌다. 특히 위험한 것은 배포가 **성공한 채 수집만 조용히 죽는** 실패다 — 렌더된 셸의 문법 오류는 메트릭 소실, 렌더된 YAML의 들여쓰기 하나는 로그 인입 정지(6일 침묵 사고와 같은 계열)다. 그래서 렌더 결과를 shellcheck·yamllint에 다시 넘긴다.
4. 남는 위험(유닛이 실제로 뜨는가)은 §11의 현행 절차(사람이 `--check` 후 `systemctl is-active`)가 담당한다.

재검토 조건은 백로그에 남긴다(FB-06): 타깃 균질화(xenial 정리)가 선행되면 비용 구조가 바뀐다.

### 3. 서드파티 액션 0. 액션 major는 실제 확인 후 핀

퍼블릭 레포의 워크플로는 공급망 공격 표면이다. 우리가 필요한 도구는 전부 러너 프리인스톨(shellcheck·jq·docker·python3)이거나 `pip install` 한 줄이라 편의 액션의 이득이 없다. `actions/checkout`·`actions/setup-node`만 쓰고, major는 `gh api …/releases/latest`로 **조회해서** 핀한다(2026-08-03 조회: checkout v7.0.1 · setup-node v7.0.0). 추측한 버전은 첫 실행에서 깨진다.

promtool도 마켓플레이스 액션이 아니라 `run:` 스텝 하나로 설치한다 — curl + `sha256sum -c` + `install -m 0755`. 버전은 라이브 실측(3.11.3)과 같은 값으로 핀하고, sha256은 릴리스의 `sha256sums.txt`를 **실제로 받아 확인한** 값을 워크플로에 리터럴로 박았다.

### 4. 러너에 시크릿 0

`next build`가 env 없이 성공함이 실측이므로 워크플로에 `${{ secrets.* }}` 참조가 **한 건도 없다**. 시크릿을 안 주면 유출될 시크릿도 없다.

### 5. `paths:` 필터를 쓰지 않는다

required status check가 skip되면 GitHub은 그것을 **영구 pending**으로 취급해 머지를 막는다. 총 소요 ~2분이고 과금이 0인 곳에서 알려진 함정을 밟을 이유가 없다.

### 6. 오탐은 허용리스트가 아니라 **규칙 재정의**로 없앤다

시크릿 게이트를 목적이 다른 4규칙으로 쪼갰다.

| 규칙 | 코퍼스 | 무엇이 위반인가 |
|---|---|---|
| S1 자격증명 리터럴 | 레포 전체(테스트 포함, **예외 0**) | 실제 자격증명 **형식** 8종 |
| S2 배포 결합 리터럴 | 런타임 소스만(테스트 제외, `next.config.ts` 포함) | 사설 IP·자체 도메인 |
| S3 번들 노출 | `.next/static` | 서버 전용 env 키 이름 |
| S4 `.env` 추적 | 레포 전체 | `.env.example` 아닌 실파일 |

오탐 14건은 예외를 파서가 아니라 **스코프와 패턴을 다시 정의해서** 사라졌다. XML 네임스페이스도, 템플릿 리터럴도 "리터럴 호스트가 없다"는 이유로 구조적으로 안 걸린다. `localhost`·`github.com`이 통과하는 것은 예외 목록이 아니라 **규칙의 정의**(배포마다 달라지는 값만 본다) 때문이다.

허용리스트(`# check-secrets:ignore` 주석이나 `.secretsignore`)를 기각한 이유: 그것은 자라면서 게이트를 무의미하게 만들고, **미탐은 그대로 남긴다.**

테스트를 S2에서 빼는 것은 면제가 아니라 스코프 정의다 — 테스트는 배포되지 않고, 스크러버 테스트는 사설 IP 마스킹을 검증하므로 픽스처를 문서용 대역으로 바꾸면 **테스트가 거짓 통과**한다. 반대로 S1은 커밋 자체가 유출이므로 테스트에도 예외를 두지 않는다.

### 7. 정규식 엔진을 `python3` `re`로 고정한다

S1 패턴은 `(?i)` 인라인 플래그·`\s`·`{10,}`를 쓰는 PCRE 문법이다. **`grep -E`에서는 `(?i)`가 리터럴로 취급되고 `\s`가 매칭되지 않아 조용히 아무것도 안 잡는다.** `grep -P`는 GNU grep 전제라 러너·노드마다 갈린다. 그래서 bash 래퍼 + `python3` 히어독 한 가지로 고정했다. 이 선택이 실제로 살아 있는지는 `--self-test`가 매 실행에서 확인한다.

구현 중 실측으로 하나 더 배웠다: python `re`의 부정 문자 클래스는 `\n`도 매칭하므로 `['"][^'"]{7,}['"]`는 **여러 줄을 건너뛰어** 다음 따옴표까지 삼킨다(문서 한 줄과 40줄 뒤의 따옴표가 한 건으로 잡혔다). 하드코딩된 값은 정의상 한 줄 안에 있으므로 값 부분에서 개행을 제외했다.

### 8. self-test 픽스처를 **파일로 커밋하지 않는다** — 런타임 조립

이 레포는 PUBLIC이고, GitHub push protection / secret scanning은 값의 **유효성과 무관하게 패턴만 보고** push를 차단한다. `ghp_` 36자·Slack 웹훅 꼴·개인키 PEM 헤더를 픽스처 파일로 커밋하면 **게이트를 도입하는 그 PR 자체가 push 불가**가 된다 — 게이트를 세우려다 게이트에 막히는 자기모순이다.

그래서 `--self-test`는 접두사를 분할 결합해(`"ghp" + "_" + "A"*36` 꼴) 소스에 완전한 패턴이 존재하지 않게 하고, `mktemp -d`에 써서 검사한 뒤 지운다. 커밋되는 것은 **생성 로직뿐**이다.

> 다음 사람에게: `apps/console/scripts/fixtures/`가 비어 있거나 없는 것은 실수가 아니다. 픽스처 파일을 만들어 넣으면 push가 막힌다. 위 이유로 **의도적으로** 런타임 생성이다.

같은 이유로 **자격증명 꼴 리터럴을 문서·스펙·커밋 메시지에 재현하지 않는다.** S1의 코퍼스가 레포 전체라 문서가 커밋되는 순간 그 문서가 히트가 된다. 값이 아니라 **위치와 구성**으로 기술한다.

### 9. 게이트 레지스트리 — 경로가 계약이다

- 레포 전역 게이트는 `scripts/gates/check-*.{sh,py}` **한 곳**에만 둔다. `scripts/verify-all.sh`가 글롭으로 순회하므로 새 게이트는 **배선 작업 0**으로 편입된다.
- `check-`로 시작하지 않는 파일(`lib.sh`·`promtool.sh`·`render-*`)은 게이트가 아니라 **헬퍼**이고, 반드시 어떤 게이트가 호출해야 한다. 아무도 부르지 않는 헬퍼는 죽은 코드다.
- 콘솔 스코프 게이트는 `apps/console/scripts/`에 남긴다. `scripts/gates/`에 **래퍼를 만들지 않는다** — 만들면 같은 검사가 두 번 돈다.
- Makefile을 만들지 않는다. 실행 경로가 둘이 되면 어느 쪽이 정본인지 사람이 판단해야 한다.
- 종료코드는 `0` 통과 / `1` 위반 / `2` 환경 부족이고, **SKIP이 1건이라도 있으면 실행기 전체가 rc=2**다. "검사가 안 돌았는데 초록"을 만들지 않기 위해서다.
- CI 워크플로는 도구 체인이 셋으로 갈려 잡별로 스텝을 **명시**한다. 로컬 글롭과 CI 열거의 비대칭은 `check-ci-coverage.sh`가 막는다 — 새 게이트를 CI에 배선하지 않으면 그 게이트가 CI를 실패시킨다.

### 10. Playwright 시각 QA는 CI 대상이 아니다

시각 QA는 **살아 있는 콘솔과 Grafana**가 필요하다(임베드 iframe·실데이터). 호스티드 러너에는 둘 다 없고, 있게 만들려면 내부망 접근이 필요해 결정 1을 깬다. `docs/testing.md`의 격리 빌드 절차(포트 3199 worktree)가 계속 담당한다.

### 11. 내부 IP·포트·계정명은 공개 레포에 남긴다 (기존 합의의 명문화)

이 스펙이 새로 만든 위험이 아니다. S2가 막는 것은 **런타임 소스에 배포 위상이 박히는 것**(환경이 바뀌면 코드를 고쳐야 하는 상태)이지, 문서에 적힌 사실이 아니다. 사설 IP는 RFC 1918 대역이라 외부에서 도달할 수 없고, 인벤토리·런북에서 그것을 빼면 문서가 쓸모를 잃는다. 자격증명은 반대다 — **하나도 남기지 않는다**(§13, S1 예외 0).

## 결과

- `.github/workflows/ci.yml` — 잡 3개(`console`·`repo-gates`·`infra-iac`). 이 이름 3개가 브랜치 보호의 required status check 이름이다.
- `.github/workflows/release.yml` — `v*` 태그에서 `verify-all.sh --with-build` 재실행 + CHANGELOG 섹션 확인. **v0.2.0이 red인 채 태그된 사건에 대한 직접 대응**이다.
- `scripts/verify-all.sh` + `scripts/gates/*` — 로컬이 CI와 같은 게이트를 돈다(build만 제외).
- 브랜치 보호 등록은 **소유자 계정에서만** 가능하다(이 환경의 `gh`는 협업자 토큰이라 403). `docs/branching.md` §7의 체크리스트가 그 절차다.

## 기각한 대안 요약

| 대안 | 기각 이유 |
|---|---|
| data03 self-hosted 러너 + 라이브 실쿼리 검증 | 3중 비용(GPU 경쟁·§12 우회 경로·새 상태저장 서비스) |
| molecule + docker 드라이버 | 초기 구축 L, CI 5~10분, xenial 경로는 재현 불가 |
| 편의 액션(`ludeeus/action-shellcheck` 등) | 공급망 표면. 대체 비용이 `run:` 한 줄 |
| `dorny/paths-filter` | 서드파티 + required check pending 함정 + 1인 운영에 무의미한 최적화 |
| `# check-secrets:ignore` 인라인 주석 / `.secretsignore` | 허용리스트는 자라고, 미탐은 그대로 남는다 |
| 스크러버 테스트 픽스처를 RFC 5737 대역으로 교체 | 사설 대역 판정 로직을 검증하는 테스트라 **거짓 통과**가 된다 |
| 로컬 verify에 build 포함 | 라이브 `.next`를 덮어써 콘솔이 죽는다(§12) |
| 임의 경로 `promtool check rules`만 | 라이브 동형 마운트가 아니면 `rule_files` 글롭 오타를 놓친다 |
