# KEIwi 디자인 원칙 (KRDS 7원칙 → 관측 콘솔 수용기준)

> **Phase 1 / SDD** — 이 문서는 KRDS 공식 디자인 원칙을 **KEIwi 관측 콘솔**의 검증 가능한 수용기준으로 번역한다.
> 이후 모든 토큰·컴포넌트·화면 스펙은 이 원칙을 충족 근거로 인용한다.

## 0. 권위·범위·출처

- **권위 순서:** `Constitution.md`(헌장) > Phase 0 확정 결정 > 이 스펙. 충돌 시 상위가 이긴다.
  특히 헌장 **§I-2(단일 콘솔=Grafana, 재구현 금지)**·**§17(브랜드/시맨틱 토큰 분리)**·**§14(인증=Cloudflare Access)**는 불가침.
- **범위:** 콘솔 **크롬**(shell·nav·플릿카드·탭·배지·Stat/헬스카드·테이블·알림 등)에 KRDS를 적용한다. **시계열은 Grafana 임베드 유지**(네이티브 차트로 대체하지 않는다 — Phase 0 결정 / 차트=defer-to-grafana).
- **KRDS 출처(원칙):** <https://www.krds.go.kr/html/site/utility/utility_02.html> (디자인 원칙). 토큰·색·타이포 등 세부 수치 출처는 각 해당 스펙에 별도 명시.
- **표기:** **MUST**(반드시) / **SHOULD**(권장) / **MAY**(선택). "AC"=Acceptance Criteria(수용기준, 가능한 한 기계·리뷰 검증 가능).

## 1. KRDS 7원칙 → 본 제품 수용기준

각 절: **KRDS 원문**(인용, 출처 그대로) → **KEIwi 해석**(관측 콘솔 맥락) → **AC**(수용기준) → **Do/Don't**.

### 원칙 1 — 사용자 중심의 서비스
> "디지털 정부 서비스에 대한 모든 의사 결정은 사용자를 중심으로 이루어져야 한다." (KRDS)

**KEIwi 해석:** 콘솔의 1차 사용자는 **KEI 운영자/관제자**다. "지금 플릿이 정상인가, 어디가 문제인가"에 **3초 내** 답하는 것이 최우선. 화면은 의사결정에 필요한 정보를 위계로 배치한다.

**AC**
- **AC1.1 (MUST)** Overview 진입 시 **플릿 상태 strip이 스크롤 없이** 한 화면에 보인다. (이미 충족 — 회귀 보호: `npm run screenshot` desktop/laptop 스크롤=0.)
- **AC1.2 (MUST)** 가장 중요한 정보(노드 상태)가 시각 위계 최상단. 보조 정보(라벨/메타)는 종속 위계.
- **AC1.3 (SHOULD)** 주요 행동(노드 드릴다운 등)은 1클릭. (#2 노드 카드 → 메트릭, 충족.)

**Do:** 상태 → 원인 → 상세의 드릴다운 경로 제공. **Don't:** 관제와 무관한 장식·모달 남발.

### 원칙 2 — 모든 사용자를 포용하는 서비스
> "디지털 정부 서비스의 사용자는 장애인, 고령자, 어린이, 외국인을 포함하여 서로 다른 능력, 환경, 상황을 가진 모든 사람으로 정의해야 한다." (KRDS)

**KEIwi 해석:** 관제 도구라도 접근성은 1급. KWCAG 2.2 / WCAG 2.1을 전 컴포넌트 게이트로 둔다.

**AC**
- **AC2.1 (MUST)** 본문 대비 **≥ 4.5:1**(AA), 큰 텍스트/비텍스트 ≥ 3:1. 매직넘버 규칙(50=4.5:1 등)을 토큰에서 강제 — 검증: 자동 대비 검사(Phase 5 CI).
- **AC2.2 (MUST)** **색상 단독으로 정보 전달 금지** — 상태/로그레벨은 **색 + 아이콘 + 텍스트** 병행(색각이상 대응). 검증: 컴포넌트 스펙 체크리스트 + 코드 리뷰.
- **AC2.3 (MUST)** 키보드 완전 조작 + `focus-visible` 가시 + 키보드 트랩 없음. 인터랙티브 타깃 **≥ 44×44px**.
- **AC2.4 (MUST)** 모든 인터랙티브 요소에 Name/Role/Value 노출(aria-*).

**Do:** `StatusIndicator`처럼 점+텍스트 병행. **Don't:** 빨강/초록 점만으로 up/down 구분.

### 원칙 3 — 공통된 경험 안에서 개별 특성을 고려한 서비스
> "디지털 정부의 모든 서비스는 기관과 서비스 유형에 상관없이 일관성 있는 표현과 설계 방식으로 구현하여 하나의 대한민국 정부 서비스로 느껴지도록 제공해야 한다." (KRDS)

**KEIwi 해석:** **KRDS 토큰·컴포넌트 패턴을 단일 기준**으로 삼아 화면 간 일관성을 보장하되, 관측 도메인 특화(밀도 높은 표, 실시간) 위젯은 KRDS 토큰 위에서 확장한다.

**AC**
- **AC3.1 (MUST)** 모든 색/간격/radius/타이포는 **토큰 경유**. 컴포넌트에 **원시 hex 금지** — 검증: `check:no-raw-hex`(기존 게이트) + 네이밍 lint.
- **AC3.2 (MUST)** 토큰 3계층(Primitive→Semantic→Component) 단방향 참조. **Primitive 직접 사용 금지**(참조 전용).
- **AC3.3 (SHOULD)** KRDS에 있는 컴포넌트는 KRDS 패턴(Anatomy/States)을 따르고, 없는 대시보드 전용 위젯만 신규 정의하되 **KRDS 토큰만으로** 스타일.

**Do:** 확장형(브랜드) 색도 KRDS 토큰 체계 위에서 정의(→ `color.spec.md`/ADR-0007). **Don't:** 화면마다 제각각 색/간격.

### 원칙 4 — 빠르고 간단한 서비스
> "…이용 과정에서 필요한 의사 결정을 최소화하는 방식으로 사용자의 경험을 설계해야 함을 의미한다." (KRDS)

**KEIwi 해석:** 관제 화면은 **인지 부하 최소화**. 기본값이 합리적이고, 시선 이동·클릭 수가 적어야 한다. 성능도 "빠름"의 일부 — 실시간 갱신이 렌더를 막지 않는다.

**AC**
- **AC4.1 (MUST)** 핵심 상태 파악에 **추가 클릭 0**(strip이 곧 답). 상세는 점진적 드릴다운.
- **AC4.2 (SHOULD)** 대용량 표(M2 로그)는 **가상 스크롤**, 차트/무거운 컴포넌트는 dynamic import.
- **AC4.3 (SHOULD)** 실시간 갱신부는 메모이제이션으로 리렌더 최소화.

**Do:** 합리적 기본 시간범위·자동 새로고침. **Don't:** 필수 정보를 다단계 메뉴 뒤에 숨김.

### 원칙 5 — 쉽게 이해하고 사용할 수 있는 서비스
> "…콘텐츠와 사용자 인터페이스가 친숙하면서도 간결하고 직관적인 방식으로 설계되어 있다." (KRDS)

**KEIwi 해석:** 라벨은 명확·약어 지양(KRDS 네이밍 철학과 동일: `bg`❌→`background`). 숫자·IP·메트릭은 **tabular-nums**로 정렬해 읽기 쉽게.

**AC**
- **AC5.1 (MUST)** 상태/단위/라벨은 한국어로 명확히("데이터 없음"≠"다운"). 약어는 의미 손실 없을 때만.
- **AC5.2 (MUST)** 수치 정렬은 `tnum`(tabular-nums) 유지.
- **AC5.3 (SHOULD)** 빈 상태/에러 상태에 다음 행동 안내(예: "인증이 필요할 수 있습니다 — 새 탭에서 열기").

**Do:** 친숙한 KRDS 컴포넌트 어휘. **Don't:** 모호한 아이콘만 단독 사용.

### 원칙 6 — 사용자의 다양한 상황을 고려하는 서비스
> "사용자마다 다른 이용 상황과 목적, 숙련도와 이용 빈도 등을 고려하여 사용자가 원하는 방식으로 이용할 수 있게 구현…" (KRDS)

**KEIwi 해석:** **관제실(NOC) 환경·와이드 모니터·장시간 응시**를 1급 상황으로 본다 → **풀폭 반응형 + 다크(선명한 화면) 토글 1급**(Phase 0 결정). 라이트/다크 어느 쪽에서도 동일한 의미·대비.

**AC**
- **AC6.1 (MUST)** 라이트/다크 **양쪽 모두** 매직넘버 대비 기준 충족(다크=선명한 화면 모드 팔레트, System색 -20/-20/-95/-90).
- **AC6.2 (MUST)** 모드 전환 시 **FOUC 없음**(쿠키/inline script 선반영 — `layout`/`tokens.spec`에 전략 명시).
- **AC6.3 (MUST)** 콘텐츠 영역 **풀폭 반응형**(360/768/1024/1280 브레이크포인트 8pt 그리드 준수).
- **AC6.4 (SHOULD)** `prefers-reduced-motion` 존중(기존 globals 규칙 유지).

**Do:** 다크에서도 상태색 의미 동일. **Don't:** 다크에서 대비 미달/색 의미 역전.

### 원칙 7 — 신뢰할 수 있는 서비스 ★(관측 콘솔 최상위 가치)
> "사용자가 서비스에 방문하여 이용을 종료하기까지, 매 순간 정부의 공식 서비스임을 분명하게 인지할 수 있으며, **최신의 정확한 정보**에 접근할 수 있도록 만드는 것이다." (KRDS)

**KEIwi 해석:** 관측 콘솔에서 신뢰 = **데이터 정확성 + 실시간 신선도**. 화면이 보여주는 상태는 **사실과 일치**해야 하고, 거짓 안심/거짓 경보를 만들지 않아야 한다. 이것이 본 제품의 **횡단 최우선 원칙**.

**AC**
- **AC7.1 (MUST)** **no-data ≠ down 불변식**(헌장 US4). 데이터 없음을 장애로 표시하지 않는다 — 검증: `lib/status.ts` 단위 테스트(기존 회귀 보호).
- **AC7.2 (MUST)** 상태에는 **3분류(정상/다운/데이터 없음)**가 색+아이콘+텍스트로 구분되어 모호하지 않다.
- **AC7.3 (MUST)** 데이터 **신선도/출처**가 드러난다(실시간 갱신 주기 표기, 메트릭 출처=Grafana 임베드 명시). 임베드가 비면 빈 화면이 아니라 원인·다음 행동 안내.
- **AC7.4 (SHOULD)** 실시간 갱신 영역은 `aria-live`로 보조기기에 적절히 알림(과도한 낭독 방지).
- **AC7.5 (MUST)** 공식성·일관 브랜드 유지(헤더 브랜드마크·명칭). 단 §17 브랜드/시맨틱 분리 준수.

**Do:** "마지막 갱신/주기" 표기, 출처 라벨. **Don't:** 오래된 값을 현재처럼, 수집 실패를 "정상"처럼.

## 2. 관측 콘솔 횡단 원칙 (위 7원칙의 본 제품 적용 요약)

1. **데이터 정확성·실시간 신뢰가 최우선**(원칙 7). 시각 디자인은 사실 전달을 돕되 왜곡하지 않는다.
2. **정보 밀도 ↔ 가독성 균형**(원칙 1·5). 표/로그는 Body small(15)·xsmall(13)을 적극 쓰되 대비·정렬 기준 유지.
3. **상태는 다중 채널**(원칙 2·7). 색 + 아이콘 + 텍스트 항상 병행.
4. **다크/NOC 1급**(원칙 6). 라이트/다크 동등 품질.
5. **토큰만이 진실**(원칙 3). 하드코딩 0, Primitive 직접 사용 0.
6. **헌장 정합**(전체). Grafana 임베드 구조 불가침(§I-2), #2 var-instance 배선 유지, 인증은 Cloudflare Access(§14).

## 3. 수용기준 요약 (검증 방법)

| AC | 검증 수단 | 시점 |
|---|---|---|

| AC2.1/AC6.1 대비 | 자동 대비 검사(매직넘버) | Phase 5 CI |
| AC2.2/AC2.3 a11y | 컴포넌트 체크리스트 + a11y 테스트 | 컴포넌트별 |
| AC7.1 no-data≠down | `lib/status.test.ts` | verify |
| AC3.2 네이밍/계층 | 토큰 네이밍 lint 정규식(→ `tokens.spec.md`) | 빌드 |
| AC6.2 FOUC | 수동 + 스크린샷(모드 전환) | layout 구현 시 |
