# infra/monitoring/metric-names.pending.txt — **아직 라이브에 없는데 이 스펙이 배포할 예정인** 메트릭
#
# 왜 이 파일이 따로 있나 (spec §0.3)
#   check-promql-metrics.sh 는 metric-names.txt(라이브 스냅샷)와 대조해 오타를 잡는다.
#   그런데 축1이 만드는 node_nvidia_* · 축2가 만드는 node_smart_* 는 **배포 전이라
#   스냅샷에 없다** → 정상 규칙이 FAIL한다. 가드는 두 파일의 **합집합**을 허용집합으로 쓴다.
#
# 형식 계약: `<메트릭명>  # spec §N <근거>`
#   근거 주석이 없는 줄은 게이트가 exit 1 로 떨어뜨린다 — "일단 넣고 보자"를 막기 위함이다.
#
# 청소 계약 (AC-4-6 ②): 라이브에 실제로 나타나면 이 파일에서 **제거해야 한다**.
#   T4-12(배포 직후 스냅샷 재생성)가 metric-names.txt 를 갱신한 직후,
#   `comm -12 <(sort metric-names.txt) <(cut -d'#' -f1 metric-names.pending.txt …)` 가
#   비어야 한다. 남아 있으면 "예정"과 "실재"가 동시에 참인 모순 상태다.
#
# 갱신: 사람이 수기. 자동 생성하지 않는다(예정 메트릭은 라이브에 근거가 없으므로).
